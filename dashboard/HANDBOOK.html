Chapter 1

What it is

A FastAPI server and a static page. The server proxies the CSE's public API, values your holdings against the live tape, holds one WebSocket connection open to the exchange and fans it out to every browser tab, and charts the price history of any listed security on demand.

It exists because a broker's portfolio screen answers the wrong questions. It reports allocation as a share count and profit against the average price rather than the break-even sale price. This system fixes both, and adds a history lookup that is not limited to what you own.

Chapter 2

Architecture, and the three constraints that forced it

Every structural decision here follows from something the CSE API will or won't do. None of it is preference.

Constraint 1 — CORS is closed, so the browser can never call CSE

POST /api/tradeSummary returns 200 with no Origin header and 403 with any foreign one; the preflight carries no Access-Control-Allow-Origin. A browser-only dashboard is impossible. Every upstream call is made server-side with the site's own Origin, Referer and a browser User-Agent — remove any of those three and you get a 403.

Constraint 2 — only one endpoint prices the whole market

todaySharePrice returns ten rows, the first ten alphabetically, over both REST and WebSocket. It cannot value an arbitrary portfolio. POST /api/tradeSummary is the only full-market price source, which is why valuation polls REST on a timer while the live feed drives only the market-wide widgets.

Don't hard-code the row count

That endpoint returned 281 rows when the API notes were written, 291 in an earlier revision of this handbook, and 286 today. The count drifts as listings change, so treat it as an observation rather than a constant — nothing in the code depends on it.

Constraint 3 — no security maps to a sector

No sector field exists in tradeSummary, companyInfoSummery, allSecurityCode or cntSecurity, and the sector-constituent endpoints 404. /api/allSectors gives the sector indices, which is enough to draw the heatmap, but mapping your holdings to sectors needs the hand-kept table in server/sectors.py.

Politeness budget

Ten open tabs must not become ten upstream calls. The TTL cache runs single-flight: concurrent callers for one key await a single in-flight fetch, and everyone else is served from memory until the TTL expires. If a refresh fails while a stale value is held, the stale value is served — a slightly old price beats an error card — and the age is reported to the page so the staleness is visible rather than silent.

KeyTTL, market openTTL, closed
tradeSummary15 s300 s
allSectors60 s60 s
chart:{id}:{period}900 s900 s

The browser polls /api/portfolio every 20 s and sectors every 60 s, so a poll usually lands on a warm cache rather than the wire. Failed upstream calls retry three times with 0.5 s, 1 s, 2 s backoff before surfacing a 502.

Chapter 3

Running it

The virtualenv lives at the repository root, not inside dashboard/. Always start the server from the repo root — dashboard.server.main is a package path.

# first time only
python3 -m venv .venv
.venv/bin/pip install -r dashboard/requirements.txt

# every time
.venv/bin/python -m uvicorn dashboard.server.main:app --reload

Then open http://127.0.0.1:8000. A healthy start prints the usual uvicorn lines and then, within a second or two, the relay:

INFO:     Application startup complete.
INFO dashboard.server.ws_relay: relay connected to wss://www.cse.lk/api/ws/websocket

If that second line never appears the page still works — prices and history come from REST — but the indices, gainers, losers and most-active panels stay on waiting for feed….

Verify without opening a browser

curl -s localhost:8000/api/health
# {"ok":true,"relayConnected":true,"marketOpen":false}

Tests

.venv/bin/python -m pytest dashboard/tests/ -q
# 27 passed

They need no network. test_portfolio.py pins the valuation maths to figures verified against live quotes, test_securities.py pins symbol resolution, and test_relay.py pins STOMP framing and timestamp normalisation.

Chapter 4

The numbers, and why they differ from your broker's

All valuation lives in server/portfolio.py as pure functions over a holdings list and one tradeSummary snapshot. Two figures deliberately disagree with the broker's portfolio screen.

Cost weight, not share-count weight

The broker's "Holding %" is qty ÷ total shares. Across the sample book's 875 shares, RCL's 500 shares are 57.14% by that measure — but at cost RCL is 25,000.00 of 55,750.00, which is 44.84%. Share-count weight systematically overstates low-priced lines and is close to meaningless for allocation. This dashboard shows cost weight and market-value weight instead.

The figures below use the placeholder positions in holdings.sample.json, not a real book.

SymbolQtyAvgCost Broker "Holding %"Cost weight
RCL.N000050050.0025,000.0057.14%44.84%
SEYB.X000020070.0014,000.0022.86%25.11%
AAIC.N000010080.008,000.0011.43%14.35%
ACL.N000050100.005,000.005.71%8.97%
SPEN.N000025150.003,750.002.86%6.73%

The two columns disagree on every line. RCL looks like 57% of the book by share count while being 45% of the capital in it, and SPEN — the most expensive line — is understated at 2.86% against a true 6.73%.

Profit against the break-even sale price

The B.E.S. price includes round-trip fees, so it is the price a line must actually clear to stop losing money. Every position carries both: pnl against the average price, and pnl_vs_bes against B.E.S. The second is always the harsher number — a unit test enforces that it can never come out better. When besPrice is absent from a holding it falls back to the average price rather than failing.

What a position is worth

market_value = qty × price
pnl          = market_value − qty × avg_price
pnl_vs_bes   = market_value − qty × bes_price
day_change   = qty × (price − previousClose)
Test fixture

The suite pins the sample book to cost 55,750.00, market value 54,895.00, P&L −855.00 (−1.53%) against a captured set of quotes. Those are fixed numbers for a fixed snapshot — the live figures move with the tape. If the tests fail on those three lines after you edit portfolio.py, the maths changed, not the market.

Missing prices

A symbol absent from tradeSummary, or priced at zero, is kept in the table flagged unpriced and listed in portfolio.unpriced. It contributes its cost to the total but no market value. Dropping it silently would misstate the book, so the gap is shown instead.

Chapter 5

The live feed

The server holds exactly one STOMP connection to wss://www.cse.lk/api/ws/websocket and rebroadcasts it. Browser tabs connect to this server's own /ws, never to the exchange. On connect the relay subscribes to both /topic/{feed} and /user/topic/{feed} for seven feeds, sends one snapshot request per feed, and then listens for broadcasts only.

FeedDrives
aspi, snpThe two index cards in the header
summaryMarket turnover, share volume, trade count
statusExchange open/closed state as the exchange reports it
top-gainers, top-loosesLeaderboards, with your symbols badged HELD
most-active-tradesVolume leaders — note these rows carry no price

Three quirks the relay absorbs

  • Silence is normal. The server negotiates heart-beat:0,0 and sends nothing when idle. The socket read uses a 5-second timeout and loops on expiry; treating silence as a dropped connection would reconnect forever.
  • Timestamps arrive in two shapes. Epoch integers on /user/topic/* replies, ISO-8601 strings on /topic/* broadcasts. normalise() walks each payload and rewrites timestamp, tradeDate, tradesTime and lastTradedTime to epoch milliseconds so the page never has to guess.
  • A slow tab cannot stall the exchange. Each subscriber gets a bounded queue of 100 messages; overflow is dropped rather than backing up the relay, and the tab re-syncs from the snapshot frame on its next reconnect.

On any error the relay marks itself disconnected, publishes that state to every tab so the feed pill goes amber, and retries after 5 seconds — the same delay the exchange's own client uses. New tabs are sent a _snapshot frame containing everything currently held, so a tab opened mid-session paints immediately instead of waiting for the next broadcast.

Chapter 6

Price history

Type a symbol, a bare ticker or a company name into the Price history card to chart any listed security and export the series as CSV. It is not limited to what you hold.

What the resolver accepts

The stockId it resolves to is the id field from tradeSummary — not the securityId returned by companyInfoSummery. Lookups run in this order, and stop at the first hit:

You typeRuleResolves to
LOLC.N0000Exact symbol, case-insensitivestockId 410
lolcBare ticker — the voting line winsLOLC.N0000
  seyb  Whitespace trimmedSEYB.N0000
softlogicCompany-name substringAAIC.N0000
ZZZZNo match404
Why the response names what it charted

SEYB.N0000 and SEYB.X0000 are different securities trading at different prices. A bare SEYB resolves to the voting line, and the other share class comes back in alternatives so the note under the chart can offer it. Charting one and staying quiet about the other would be wrong in a way nobody would notice.

Periods

PeriodValuePoints
Intraday1~300 individual trades
1 week25 sessions
1 month320 sessions
1 quarter460 sessions
1 year5240 sessions

Values 6 and 7 silently alias to 2 upstream, so the picker does not offer them and the endpoint rejects them with a 400.

CSV export

The export is built in the browser from the series already charted, so the file and the picture can never disagree. Daily periods write date,close,high,low,volume; intraday writes timestamp,… with the time of each trade. The filename carries the security and period, e.g. LOLC.N0000_1year_2026-09-08.csv.

Field notes

volume is the series' q field, which matches tradeSummary.sharevolume exactly on the latest point — that is how it was identified. The series also carries s, which looks like a statistic but is a row id (on intraday it equals the trade's own id), so it is deliberately dropped rather than exported as a number someone might sum.

o, c, pc and n come back null on daily series and are not exported either.

Prices are unadjusted

CSE's chart endpoints return raw traded prices with no back-adjustment for corporate actions. ACL.N0000's roughly 3-for-1 split on 2025-12-29 appears in its own series as a 67% crash. The note under every chart says so, because the alternative — quietly smoothing it — would hide a real event. A step change may be a change in share count rather than value.

Colombo midnight

Daily points are epoch milliseconds at Colombo local midnight. The page formats them with an explicit Asia/Colombo time zone: formatting in UTC would render every date one day early, and would do it on any machine, not just one abroad.

Chapter 7

API surface

Everything the page uses. All local, all unauthenticated.

RouteReturns
GET /api/healthok, relayConnected, marketOpen
GET /api/portfolioValued book, plus asOfAgeSeconds so the page can show price age
GET /api/holdingsThe raw holdings list
PUT /api/holdingsValidates, then writes atomically via temp file + os.replace
GET /api/securitiesEvery symbol with its stockId, for the picker
GET /api/stock/history?symbol=&period= — resolved security, its series, and any other share class it could have meant
GET /api/sectorsSector indices, best first, nulls last; ASPI and S&P removed
GET /api/marketFirst-paint snapshot of every relay feed
GET /api/chart/{stock_id}Series by numeric id, for the table sparklines
WS /wsSnapshot frame, then one message per upstream broadcast

Upstream endpoints consumed

tradeSummary, allSectors, marketStatus, marketSummery, aspiData, snpData, topGainers, topLooses, mostActiveTrades, companyChartDataByStock, chartData.

One shape trap worth remembering: companyChartDataByStock wraps its series in a {"chartData": [...]} envelope, where chartData returns a bare list.

Chapter 8

Runbook

SymptomCause and fix
502 upstream unavailable Three retries to CSE all failed. Check the exchange is up; if it is, the request headers are the usual culprit — Origin, Referer and a browser User-Agent are all required by the upstream.
Feed pill stuck on connecting The relay is retrying every 5 s. Look for relay error: in the server log. Prices and history are unaffected — they come from REST.
Prices frozen, age pill climbing The cache is serving a stale value because refreshes are failing. This is deliberate. asOfAgeSeconds tells you how stale; the underlying failure is in the log.
A row reads unpriced That symbol is not in tradeSummary — a typo, a suspension, or a delisting. Check the exact ticker including the .N0000 / .X0000 suffix.
"no security matches …" The label did not resolve. Try the bare ticker, or part of the company name; the picker's dropdown lists every symbol the server knows.
History charts the wrong share class A bare ticker resolves to the voting line. Type the full symbol — the note under the chart names the alternatives it found.
A chart shows a crash you don't recognise Almost certainly a corporate action, not a collapse. Prices are unadjusted; check the security's split history around that date.
Export CSV does nothing The button stays disabled until a series has loaded. If a chart is showing and it still does nothing, check the browser console — the download is a blob created in the page.
ModuleNotFoundError: dashboard uvicorn was started from inside dashboard/. Start it from the repository root.
Chapter 9

Limits, and what not to trust

Not verified

The symbol-to-sector table in server/sectors.py is entered by hand and has not been checked against an authoritative CSE source. Sector exposure and the held outlines on the heatmap are only as good as that table. Treat it as a starting point and correct it as you find errors; unmapped symbols fall through to Unclassified rather than being dropped.

No authentication

holdings.json is a plaintext local file and nothing in this system checks who is asking. Anyone who can reach the port can read your book and rewrite it through PUT /api/holdings. Bind to localhost. Do not deploy this as-is.

  • Nothing is kept. This system stores no history of its own — every figure on the page is fetched live and gone when the process exits. tradeSummary, allSectors and dailyMarketSummery only ever answer with today, so a day's breadth, turnover and foreign flows cannot be recovered afterwards, and no record exists of what your book was worth on any past day. The chart endpoints reach back about a year, but only as prices.
  • Market hours are hard-coded as 09:30–14:30 weekdays. Public holidays are not known to the clock, so the page may claim "open" on a day the exchange is shut.
  • Every price series is unadjusted, sparklines included. A line crossing a corporate action is misleading in exactly the same way, whether it is 68 pixels wide in the holdings table or full width in the history card.
  • The security list is a snapshot too. The picker is built from the same cached tradeSummary as everything else, so a security suspended today simply will not be offered.
